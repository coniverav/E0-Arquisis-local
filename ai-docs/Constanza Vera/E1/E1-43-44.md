## Declaración de uso de IA — E1-43 y E1-44: Propuestas y máquina de estados de negociación

Para el desarrollo de las tarjetas **E1-43 — Crear y publicar `negotiation-proposal`** y **E1-44 — Implementar máquina de estados de negociación** se utilizó ChatGPT como herramienta de apoyo mediante consultas por chat.

La herramienta se utilizó principalmente para:

- Revisar el estado actual del backend y las dependencias ya implementadas antes de abordar E1-43 y E1-44.
- Relacionar las tarjetas con las funcionalidades existentes de publicación AMQP, idempotencia y reglas de negociación.
- Diseñar el flujo para crear y persistir una `negotiation-proposal`.
- Proponer la reutilización del mecanismo de outbox existente mediante `OutboundMessage`, evitando realizar publicaciones directas a RabbitMQ desde el backend.
- Diseñar el servicio encargado de crear una negociación, generar su `idpk` y `msgId`, construir el payload del protocolo y dejarlo pendiente de publicación.
- Integrar las reglas implementadas previamente para validar dirección, cantidad, precio máximo y capacidad disponible.
- Diseñar una máquina de estados centralizada para las negociaciones.
- Definir y organizar los estados `PENDING_PUBLICATION`, `PROPOSED`, `ACKNOWLEDGED`, `CONFIRMED`, `PAID`, `REJECTED` y `TIMEOUT`.
- Definir las transiciones permitidas entre estados y evitar regresiones provocadas por mensajes atrasados.
- Diferenciar correctamente un `ack` de una confirmación efectiva de negociación.
- Integrar las transiciones de estado con la publicación de la propuesta y con la recepción de `ack`, `give`, `take`, `transfer` y `error`.
- Mantener la correlación entre los distintos mensajes mediante `latest_msg_id`, `target` y `becauseOf`.
- Proponer que el plazo de 30 segundos comience desde la publicación efectiva de la propuesta y no desde su creación local.
- Dejar preparada la máquina de estados para las posteriores tarjetas de timeout y retry, sin implementar anticipadamente E1-49 y E1-50.
- Diseñar tests para comprobar la persistencia de las propuestas, creación del mensaje outbound y funcionamiento de las transiciones de estado.
- Apoyar la ejecución de los tests dentro del entorno Docker del proyecto.
- Analizar problemas de ejecución relacionados con el entorno local de Python, dependencias y disponibilidad de `sqlmodel`.
- Diagnosticar problemas de Docker Compose relacionados con PostgreSQL, el puerto `5432`, el contenedor de migraciones y el levantamiento de los servicios.
- Indicar la ubicación exacta de los cambios requeridos en `main.py` para asociar los errores de protocolo a una negociación y llevarla al estado `REJECTED`.
- Explicar cuándo reconstruir las imágenes Docker para que los cambios locales del código fueran incorporados a los contenedores.
- Preparar un resumen técnico de ambas tarjetas para documentar la Pull Request.

ChatGPT no realizó modificaciones autónomas sobre el repositorio. Las propuestas de código, estructura, tests y comandos fueron revisadas, copiadas y ejecutadas manualmente antes de ser incorporadas al proyecto.

La implementación se desarrolló reutilizando la infraestructura existente del proyecto para persistencia, outbox y publicación mediante el connector. Durante el proceso se utilizaron tests específicos y comandos de Docker Compose para revisar el comportamiento de la solución y diagnosticar problemas del entorno de ejecución.
