# E1-39 — Request de información faltante

## Uso de IA

Se utilizó IA como apoyo para analizar el flujo definido para E1-39 y proponer una implementación consistente con la arquitectura existente del proyecto.

La asistencia se utilizó principalmente para:

- Revisar el mecanismo existente de persistencia y publicación de mensajes salientes.
- Diseñar la generación persistente de mensajes `request` utilizando el outbox existente.
- Implementar la detección automática de un `status-statement` faltante cuando llega un mensaje asociado a un ciclo sin estado inicial.
- Mantener la publicación RabbitMQ aislada en el connector.
- Incorporar la correlación entre una solicitud publicada y la respuesta posterior recibida desde la central.
- Incorporar soporte para solicitudes de `status-statement` y `distance-table`.
- Agregar pruebas de creación, deduplicación, despacho, publicación, correlación y solicitud automática.
- Revisar errores de integración e indentación detectados durante las pruebas.

La implementación fue revisada y ejecutada localmente.
