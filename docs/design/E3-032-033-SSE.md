# E3-032 / E3-033 — Backend SSE

## Entrega

- Nuevo endpoint autenticado `GET /events/stream`, validación Auth0 JWT con `sub` y scope opcional `SSE_REQUIRED_SCOPE=read:events`.
- Nueva migración `e3032ssefeed` de `inbound_messages`, `outbound_messages` y `wallet_reconciliations` a un registro público transaccional y ordenado.
- Respuestas SSE de lista blanca; sin claves, payloads internos, `swapToken`, idpk ni `msgId`.
- `Last-Event-ID` y comentarios keepalive; consultas breves a PostgreSQL desde el servidor (no polling HTTP del navegador).

## Aplicación

1. Crear rama nueva a partir de `develop` en backend.
2. Descomprimir archivos del ZIP en la **raíz del repositorio**.
3. Ejecutar `python3 scripts/apply_e3_032_033.py` para registrar el router en `master/app/main.py`.
4. Revisar los cambios con `git diff`.
5. Preparar PostgreSQL de test que cumpla con la convención `energyshark_test_*`, instalar dependencias de `master/requirements.txt` y ejecutar `cd master && pytest -q tests/test_e3032_e3033_sse.py`.
6. Ejecutar suites de regresión E2/E3. Sólo aplicar `alembic upgrade head` a producción tras autorización, backup y plan de despliegue.

## Restricciones

- El feed ofrece **hechos persistidos**, no un sustituto del estado real de la Wallet ni de Step Functions.
- Los eventos se producen desde que se instala la migración. No se inventa historia anterior.
- El backend consulta la tabla con una espera de 1,5 segundos entre lotes vacíos; el navegador no hace polling.
- Se requiere revisar el modo de streaming/buffering real del API Gateway desplegado y admitir `Last-Event-ID` en CORS antes de la prueba productiva.
- E3-034 y E3-052–054 permanecen independientes de este incremento.
